# VisionFlow Automator

## 视觉识别自动脚本使用说明

VisionFlow Automator 通过识别屏幕或指定窗口中的 PNG 模板，自动执行鼠标点击、键盘输入、键盘移动和鼠标拖曳操作。它适合将重复的界面操作编排成可重复执行的任务流程。

> 注意：脚本会实际移动鼠标并发送键盘输入。第一次运行请关闭循环，只启用少量步骤测试。

## 1. 功能概览

- 识别 PNG 模板并点击界面元素。
- 按目标窗口区域识别，支持窗口不在前台时工作。
- 使用备用点击点和一个或多个识别区域提高稳定性。
- 一个步骤可以绑定多张候选模板，并可选择"命中多张时挑哪一张"的策略（置信度最高 / 最左 / 最右 / 最上 / 最下）。
- 等待画面变化、下一模板出现等结果条件。
- 使用 `custom` 和用户创建的预设（`tasks.py` 里内置的 `daily` / `side` 目前被删除名单屏蔽，见 §6.1）。
- 创建组和子组，启用/停用、排序、复制和批量删除任务。
- 蓝图中支持组容器、组收起/展开、组整体移动和步骤归组管理。
- 使用 Ctrl/Shift 多选，按 Enter 批量启用或关闭步骤。
- 执行键盘移动、单次按键、鼠标拖曳、持续点击、延迟和循环步骤；条件、选择、事件步骤也能执行，但它们**不在「新增步骤」下拉里**（创建方式见 §4.3）。
- 循环执行完整任务队列，停止时可中断大多数等待和操作。
- 支持蓝图连接点、分支、步骤布局、调试运行和流程检查。

## 2. 安装与启动

### 2.1 环境

- Windows
- **Python 3.10 或更高版本**（**不是 3.9**：`numpy 2.2.6`、`PySide6 6.11`、`Pillow 12` 都要求 `>=3.10`；本工程在 **3.10.8** 上开发与验证）
- 目标程序允许模拟鼠标和键盘输入

在项目目录打开 PowerShell，**按锁定版本安装依赖**（推荐）：

```powershell
python -m pip install -r requirements.txt

可选：文字识别（OCR）。需要"点文字按钮"的功能要先装后端（不装也能正常用其它功能）：



```powershell

python -m pip install -r requirements-ocr.txt

```



装的是 `rapidocr-onnxruntime`（onnxruntime + 内置中文模型，约 15 MB，纯 CPU、离线运行）。装好后重启程序即可在识别型步骤里勾选「用文字识别代替模板（OCR）」。
```

`requirements.txt` 锁的是本工程实际验证过的版本。如果不使用它、直接安装最新版也可以，但**行为可能与已验证版本不同**：

```powershell
python -m pip install numpy opencv-python mss pyautogui pygetwindow PySide6
```

如果电脑上有多个 Python，请显式指定解释器，并确认它与启动程序用的是同一个：

```powershell
py -3.10 -m pip install -r requirements.txt
```

> `Pillow` 会被 `pyautogui` 自动带上，无需单独安装。

当前版本使用 `gui_pyside6.py` 的 PySide6 主界面（唯一维护中的界面）。

> **关于 Tkinter 版 `gui.py`**：该界面已于 2026-09-28 **退役**，随后连同 `legacy/README.md`
> 一并**删除**（提交 `26b098c`）——现在工程里已经没有它了。
> 删除原因：它**不再维护**，且含有若干**已知的数据破坏性问题**——它与新界面共享同一批 JSON
> 数据文件，运行并保存可能覆盖新界面的数据。
> 仅需查阅旧实现时，从 git 历史取回即可（**只读代码，不要运行它去打开现有数据**）：
>
> ```powershell
> git log --oneline --follow -- legacy/gui.py      # 查看完整历史
> git checkout <commit> -- legacy/gui.py           # 从任意提交恢复
> ```

### 2.3 启动（打包版，对方不需要装 Python）

工程内附有 PyInstaller 打包规格，构建产物是一个**免安装目录**：

```text
VisionFlow_Automator_打包版\
├─ VisionFlow_Automator.exe     ← 双击运行
└─ _internal\                   运行库与 icons 资源（不要删除、也不要单独移动）
```

- 把**整个目录**拷到目标电脑即可运行（Windows 10/11 64 位，不需要装 Python）。
- **必须放在可写目录**（桌面、`D:\` 下的自建目录等）。**不要放进 `C:\Program Files`**——程序运行时要往 exe 同级目录写数据文件，那里默认没有写权限。
- 4 个数据文件（`saved_tasks.json` 等）就在 **exe 同级目录**，与源码运行的规则一致；想换位置可设置环境变量 `VF_DATA_DIR`。
- 启动后日志框会打印 `[打包运行] 资源目录=…；数据目录=…`，可据此确认它读的是哪份数据。
- 详细的构建/裁剪方法见 `docs/项目接手文档.md` §10；`.spec` 就是构建规格。

**改完代码后重新打包（一键）**：双击 `打包.bat`，或在本目录执行 `python build_package.py`。脚本按「预检 → 构建 → 部署 → 校验 → 收尾」五步走：

- 构建中间物放在 `%TEMP%` 下，**不污染工程目录**；
- 部署时**只替换程序部分**（exe 与 `_internal`），分发目录里的 4 个数据文件**逐字节保留**；
- 校验内容：数据文件哈希未变、exe 与构建产物一致、勾选框所需的 SVG 插件 / 软件 OpenGL / `tkinter` 都在位、模板库非空；
- 任何一项不过就以非 0 退出码结束并列出问题（`2`=预检 `3`=构建 `4`=校验）。

```powershell
python build_package.py                             # 构建 + 部署
python build_package.py --zip                       # 顺便打一个 zip，便于发给别人
python build_package.py --sync-data                 # 把工程里的数据文件同步到分发目录（先备份原有那份）
python build_package.py --build-only                # 只构建，不动分发目录
python build_package.py --from-dist <已有产物目录>   # 跳过构建，只更新分发目录
```

## 3. 第一次运行

1. 打开目标程序，进入目标控件可见的页面。
2. 点击“刷新窗口”，在“目标窗口”下拉框选择目标程序。
3. 在“执行功能”中选择 `custom` 或目标预设。
4. 只启用一个已配置步骤，确认“循环执行”未勾选。
5. 点击“开始执行”。
6. 查看日志中的模板、置信度和点击坐标。
7. 确认无误后，再逐步启用其它步骤或整个组。

如果目标窗口列表为空，程序会使用当前活动窗口或屏幕区域。窗口移动、缩放或改变大小后，应重新检查点击点和识别区域。

## 4. 界面操作

### 4.1 顶部控制区

- **循环执行**：任务队列完成后从第一步重新执行。
- **执行功能**：切换 `custom` 和用户预设。
- **预设 ▾**：低频管理动作收进下拉菜单（新建/重命名/复制/导入/导出/删除，运行中自动禁用）；「保存」常驻在菜单右侧，也可以按 `Ctrl+S` 保存。
- **底部状态栏**：目标窗口选择 +「刷新窗口」、状态胶囊（待机/运行中/暂停/异常/完成/停止）、当前预设、最后保存时间；运行时显示进度条；右侧「使用说明」（打开 README）与「关于」（版本/程序目录/数据目录）。
- **运行反馈**：执行时高亮当前步骤行（加粗+浅蓝底）、成功绿字、失败/超时红底红字；列表为空时显示引导提示，编辑器未选步骤时提示「从左侧选择一个步骤」。
- **新建预设**：创建空白预设。
- **重命名预设**：修改当前预设的名称（`custom` 不可改名）。
- **复制到预设**：把当前选中的组或步骤追加到其它预设。
- **删除预设**：删除当前预设及全部步骤；`custom` 不能删除。
- **导出预设**：将当前预设导出为 ZIP，包含全部步骤、步骤设置、分组、蓝图连接、蓝图布局和绑定 PNG 图片。
- **导入预设**：从 ZIP 恢复预设和全部图片；导入图片会写入本地 `icons` 文件夹，并可选择新的预设名称或覆盖同名预设。
- **保存当前任务**：把当前预设的内容立即写回磁盘（`custom` → `saved_tasks.json`，其它预设 → `saved_presets.json`）。多数编辑动作本身就会保存（「应用修改」、勾选启用、增删/移动步骤等），这个按钮用于想**立刻确认落盘**的场合。
- **目标窗口**：从刷新后的窗口列表中选择目标窗口。
- **刷新窗口**：重新读取当前可见窗口标题。
- **状态**：顶部右侧显示当前状态（待机 / 运行中 / 暂停等）。
- **开始执行/停止**：启动或停止任务队列；停止会中断识别等待、延时、持续点击和拖曳。
- **执行前体检**：点「开始执行」时会先扫一遍要跑的步骤——模板文件不存在、`等待方式=下一模板出现` 却没配下一模板、跳转目标越界或指向已禁用步骤、点击坐标超出屏幕、识别区域非法等。发现问题会弹窗列出，可以「仍然开始」或「自动修复可安全项」；**没有问题时不会弹窗**，与以前一样直接开跑。
- **识别调试**：打开后显示最近一次识别的画面、用了哪张模板、得分 / 阈值、命中坐标与耗时（命中位置画红框），可暂停刷新仔细看。
- **兜底处理**：编辑一组「通用恢复步骤」（关弹窗 / 点继续 / 等待加载）。识别失败时（重试用完、进入迂回前）按顺序尝试，任一步骤成功就重新识别当前步骤；每个步骤每次运行最多尝试一轮。
- **检查更新**：启动后会在后台查一次 GitHub 最新版本，有新版本会提示并可一键打开发布页；断网 / 接口限流时静默跳过，不影响使用。想手动检查点面板上的「检查更新」按钮。
- **片段**：把常用的一组步骤存成片段，之后在任意预设里一键插入。用法：在左侧列表选中若干步骤**或整个分组** → 面板「片段」按钮 → 保存选中步骤为片段；要复用时选好插入位置 →「插入片段」。**插入位置**：选中步骤时紧接在它之后；选中分组时接在该组最后一个步骤之后；什么都没选则追加到末尾；把带分组的片段插进某个组里时，片段的顶层分组会变成该组的**子组**（组可以套组）。只含分组、没有步骤的片段也能**保存和插入**（会建出分组结构）；重复插入同一片段时组名会自动加「副本」后缀，同时选中多个组时按「最外层」确定父组并在日志里说明，插入到收起的组会自动展开。片段保存在 `saved_presets.json` 的 `__snippets__` 里（**全局共享**），格式为 v2（步骤 + 分组名称/颜色/嵌套关系；旧的纯步骤片段仍兼容）；保存时只保留片段内部的跳转（相对编号），插入时会自动把后面的步骤跳转整体后移，片段内部的条件/循环连线仍然连在一起。
- **全局停止快捷键**（默认 `Ctrl+C`）：通过系统级 `RegisterHotKey` 注册，脚本运行期间即使窗口在后台、最小化或脚本正在抢占鼠标/键盘，按 `Ctrl+C` 也会立即停止并释放卡住的按键和鼠标。注意：热键只在**脚本运行期间**生效，脚本停止后自动注销，`Ctrl+C` 恢复正常复制功能；运行期间按 `Ctrl+C` 会被脚本拦截（不会执行复制）。可在 `config.py` 的 `STOP_HOTKEY` 修改组合键（如 `ctrl+alt+f9`、`ctrl+shift+8`），每次执行时日志会显示当前生效的热键。
- **暂停/继续**：在步骤边界暂停或恢复执行。
- **单步**：暂停状态下只执行一个步骤。
- 暂停后每点击一次“单步”只执行一个完整步骤，步骤结束后自动恢复暂停。
- **从当前步骤执行**：从当前选中的步骤开始运行。

### 4.2 项目列表

左侧列表显示当前预设的组和步骤，步骤前的勾选标记表示启用状态。

- 单击组或步骤：在右侧打开编辑内容。
- 双击步骤：切换启用状态。
- 按住 `Ctrl` 单击：选择多个不连续项目。
- 按住 `Shift` 单击：选择连续范围。
- 选中项目后按 `Enter`：批量切换启用状态。
- 选中组后按 `Enter`：切换该组及子组内步骤。
- **工具按钮**：面板上直接摆 5 个全局功能入口（打开蓝图流程 / 识别调试 / 兜底处理 / 片段 / 检查更新），不需要展开菜单。
- **右键菜单**：项目列表面板上**不再放编辑按钮**，所有列表操作都在右键菜单里，按右键的对象自动切换：
  - 右键**步骤** → 复制 / 删除 / 上移 / 下移（无选中时置灰）
  - 右键**分组** → 编辑组设置 / 重命名分组 / 更改分组颜色 / 折叠或展开该组 / 在此组中新增步骤与子组 / 删除该组及其步骤 / 仅删除该组（步骤移到上一级分组）
  - 右键**空白处** → 新增步骤 / 新增组 / 全选 / 清空 / 打开蓝图流程
- **列表快捷键**：列表获得焦点时支持 `Del` 删除、`Ctrl+C` 复制、`Ctrl+A` 全选、`Ins` 新增步骤、`Ctrl+↑/↓` 移动、`Ctrl+Z` 撤销、`Ctrl+Y` / `Ctrl+Shift+Z` 重做（不影响编辑框里的按键）。右键菜单顶部也有「撤销 / 重做」。
- **拖拽**：步骤行最右侧的 ≡ 手柄可拖动。拖到**组头上沿**＝放到该组前面（可排到子组上方）、拖到**组头下沿**＝加入该组（空组也行）、拖到**空白**＝移出分组回根层、拖到**别的组的步骤**上＝改到那个组。**多选后拖任一选中步骤的 ≡ 手柄＝整块移动**（保持选择顺序，进组/组前/根层/步骤前后都支持）。**分组行整行可拖**：拖到另一个组上＝变成它的子组、拖到**某个步骤**上＝把整组插到该步骤前（上半）或后（下半）——子组因此可以放在父组的两个步骤之间；拖到空白＝回到根层。
- **分组操作**：双击组行可折叠/展开；右键分组的「上移/下移」或直接拖动可调整层级与顺序——**组的顺序就是执行顺序**（界面里看到的步骤上下顺序与脚本实际执行顺序一致）；「在此组中新增子组」会真的建在组内。
- **复制**：多选步骤会复制全部；选中分组会连同子组和组内步骤一起复制（新组名带「副本」）。

- **全部启用/全部停用**：一键启用/停用所有步骤（右键菜单里）。
- **上移/下移**：调整项目顺序。
- 拖动行右侧 `☰`：调整顺序或移动到其它组。
- 组颜色：在组设置中从预设颜色表直接选择组颜色。
- **新增组/新增步骤**：创建组或任务；空预设新增步骤不会自动创建组。
- **复制**：复制当前列表中的选中项目。
- **删除**：批量删除所有选中步骤或组，删除组会同时删除组内步骤。

### 4.3 蓝图流程

主界面保持项目列表和步骤编辑器布局，点击“打开蓝图流程”会另开窗口；蓝图窗口左侧是大画布，右侧是当前步骤设置。点击步骤可同步编辑，拖动步骤可调整画布布局。普通灰色箭头表示顺序执行；启用迂回后，绿色“识别成功”和橙色“未识别”箭头分别指向对应跳转步骤。

- 蓝图步骤类型共 10 种。**可直接用「新增步骤」创建的有 7 种**：普通、循环、延迟、键盘移动、按键、拖曳、持续点击；**条件（`condition`）、选择（`switch`）、事件（`event`）不在「新增步骤」下拉里**，需要先新增一个普通步骤，再在蓝图里右键步骤 →「更改当前步骤类型」改成它们。（原「高级（`advanced`）」已取消：它与普通的唯一差别是"多张候选模板时挑哪一张"，现在由步骤面板上的「多模板时」下拉框显式选择，旧数据里的 `advanced` 仍按它原本的语义"最左"执行。）
- 蓝图画布支持 Ctrl+鼠标滚轮缩放，按住鼠标中键可平移画布。从步骤右侧输出连接点拖到另一个步骤左侧输入连接点可建立下一步连接；右键点击连线可删除连接，右键空白处可新建步骤。
- 连线的手感：鼠标悬停到连接点上会亮起白圈并变成十字光标（按下前就能看清会连哪个口）；按在连接点外侧几个像素、或拖到目标步骤外侧几个像素松手，都能正常连上。**画布缩得很小的时候相邻连接点只差几个像素**，这时先按 Ctrl+滚轮放大再连会更稳。
- 批量处理连线：**Ctrl+鼠标右键拖动**划过哪些线就切断哪些（划过时先标红，松手一次切完）；**按住 Ctrl 从空白处拖动**可以只框选连线，选中后高亮，按 Delete 或右键「删除选中的 N 条连接」一次删除。不按 Ctrl 的框选仍然只选步骤，所以「删除选中的步骤」不会误删穿过的连线。
- 蓝图支持组容器。双击组头可收起或展开，拖动组头或组边框可整体移动组内步骤（**框选多个组后拖任一选中组 = 一起移动**）；展开组背景透明，仅组头使用组颜色。
- **收起后的组 = 一个群组节点**（Blender 式）：画成带标题、步骤数和左右端口的卡片，组内节点与内部连线隐藏，**跨出组的连线自动连到这个群组节点上**；拖动卡片可整体移动组。框选时组框也会被选中（展开组的内容区是透明的，框住组体或在组内空白拖框同样能选中组）。**卡片的端口也能手动拉线**：从右端口拉出 = 从组内最后一步出去，拉到左端口 = 接到组内第一步（卡片之间也能直接连）。子组折叠后会缩成卡片，父组/根组的框也随之收紧，不会继续占着隐藏节点的位置。
  **片段（Blender 式群组）**：画布右键「片段（群组）」→「保存选中为片段…」把选中的节点/组存成片段；「插入片段」会把片段放到鼠标位置，按片段原样插入（片段自带分组就保留其分组结构；没有分组就是独立步骤，不再自动包一层同名群组节点）。分组右键也有「保存该组为片段…」「插入片段到该组」。
- **双击群组节点进入子图**：只显示该组及其子组的内容，上方显示面包屑（`根层 › 组A › 组B（N 步）`）与「← 返回上级」「根层」按钮；返回上一级有 3 种方式：**双击画布空白处**、按 `Esc`、点「← 返回上级」（嵌套时一次退一层，根层双击空白无操作）。子图里右键空白处「新建步骤 / 新增组」会落到当前进入的组里。
- 右键组可新增子组、编辑组设置或删除组；右键步骤可加入任意组或移出当前组到根组。
- **子图（进入组内部）**：右键组头 → 「进入该组内部（子图）」后，画布只显示这个组及其子组的内容，上方显示面包屑（`根层 › 组A › 组B（N 步）`）与「← 返回上级」「根层」按钮，聚焦时按 `Esc` 也能返回上一级。子图里可以正常编辑/连线/拖拽，收起组与折叠子组的行为不变。它是**纯视图**功能：步骤执行顺序不变，也不会把"当前进到哪个组"写进任何数据。
- 蓝图组被选中时，右侧显示组设置，可修改组名称、颜色和展开状态。
- 点击步骤或连线会以白色描边提示当前选择；在空白处按住左键拖动可框选多个步骤，选中多个步骤后可整体拖动。右键步骤可复制、删除、粘贴或更改步骤类型。
- 蓝图窗口支持 Ctrl+Z 撤销、Ctrl+Y 重做、Ctrl+C 复制和 Ctrl+V 粘贴；工具栏提供自动排列、对齐选中和网格吸附，右键步骤可编辑注释。
- 执行工具栏支持“暂停”“继续”“单步”和“从当前步骤执行”；蓝图运行时会用颜色显示当前、成功和失败节点，并高亮实际经过的主线连线。
- 点击蓝图窗口中的“检查蓝图”可检查非法连接、循环连接和不可达步骤；检查不会执行任务。
- 底层已加入 `Node`/`TaskNode` 适配层，统一提供 `execute`、`validate`、`inputs`、`outputs` 接口；旧版任务字典仍可直接运行。蓝图布局保存到独立的 `saved_blueprint_layouts.json`，与执行任务数据分离。
- 执行队列已通过 `NodeGraph` 解析步骤 ID、入口和多出口目标；步骤与连接关系会保存到 `saved_blueprint_graphs.json`，任务 JSON 保留为兼容导入格式。
- 任务和预设加载时会统一迁移旧字段，自动补齐步骤 ID、类型和启用状态；“检查蓝图”同时使用 `NodeGraph.validate()` 和现有连接检查。
- 右键步骤可重命名、更改步骤颜色或折叠步骤；折叠后步骤会缩短为紧凑尺寸，连接点会自动保持在步骤中心。
- 双击蓝图步骤可快速折叠或展开步骤。
- 右键连线后选择“在线上添加转折点”，转折点会直接添加在鼠标所在的线上；同一条线可以添加多个转折点。白色转折点可直接拖动改变线形，右键转折点可删除；转折点会随连线保存。
- 按住 Ctrl 点击步骤可追加或取消选中步骤；框选或 Ctrl 多选后，直接拖动任一已选步骤即可让整个选区一起移动。
- 普通步骤右侧的橙色出口表示“未识别”，绿色出口表示“识别成功”。从对应出口连接点拖到目标步骤左侧输入连接点，会直接设置迂回跳转并自动启用迂回；中间白色连接点仍表示普通顺序连接。
- 图像识别步骤的设置中包含“匹配阈值(0-1)”。未单独设置时使用 `config.py` 的 `THRESHOLD`，修改该配置可统一改变默认步骤的匹配阈值；循环、按键、移动、拖曳、延迟和选择步骤不显示此设置。
- 蓝图连接点会根据连接状态显示：已经连接的输入/输出连接点使用高亮色，未连接的连接点显示为灰色；普通顺序、未识别、识别成功和超时出口都会实时更新。
- 蓝图制作完成后点击“应用蓝图”，会保存当前预设中的全部步骤、普通连接和迂回分支，并刷新主界面的项目列表与步骤设置。
- 应用蓝图时，显式主线连接会重建主界面的步骤顺序。例如将 `1 -> 2` 改为 `1 -> 3` 后，未被继续连接的步骤会按原顺序补到后面，主界面同步显示为 `1、3、2`；迂回跳转编号也会自动同步。
- 蓝图窗口右侧使用与主界面相同的步骤变量和保存接口，包含步骤名称、模板、点击点、识别区域、下一模板、等待方式、超时、点击选项和迂回设置；**各类型的专用字段也在蓝图窗口内直接编辑**（键盘移动 / 按键 / 拖曳 / 持续点击 / 延迟 / 循环 / 条件 / 选择 / 事件），不需要切回主界面。
- 选中不同类型的蓝图步骤时，右侧会自动切换到对应设置界面；普通步骤显示通用识别设置，键盘移动、按键、拖曳和持续点击步骤显示各自的专用设置。
- 存在蓝图主线连接时，执行器会从无入线的入口步骤开始，沿连接执行；没有蓝图主线的旧任务继续按列表顺序执行。运行期间打开蓝图窗口时，当前执行步骤会自动高亮。
- 可新增“延迟步骤”，延迟期间支持停止脚本。
- **条件步骤**（把普通步骤右键改成 `condition`）：配置一个或多个模板与 `all` / `any` / `not` 运算，分别从橙色“不成立”和绿色“成立”连接点连接目标步骤。当前蓝图采用单路径顺序执行，不支持并行连接；多个出口用于条件选择或迂回跳转，不会同时执行多个分支。
- **选择步骤**（`switch`）：配置当前选择值、`值:步骤号` 分支和默认步骤号，执行时按值跳转。
- **循环步骤**（`loop`，可直接新增）：配置循环次数、循环体步骤号和退出步骤号，循环体完成后回到循环步骤，达到次数后退出。
- **事件步骤**（`event`）：配置事件模板后等待该模板出现，出现即继续蓝图；等待超时可配置跳转到指定步骤。
- 条件、选择、循环和事件步骤统一通过执行器解析下一步骤出口，同时兼容旧版迂回跳转配置。
- 普通步骤的橙色出口表示未识别，绿色出口表示识别成功，黄色出口表示超时；等待模板消失、出现或画面变化失败时也会进入黄色超时出口。条件节点支持多个模板的 `all`、`any` 和 `not` 运算。

### 4.4 界面版本

- `gui_pyside6.py`：**当前唯一维护中的界面**。使用 PySide6 原生控件和图形场景，提供树形任务列表（支持嵌套分组）、Qt 蓝图画布、线程化执行状态回传和透明屏幕采集覆盖层。

## 5. 模板图片

### 5.1 命名

程序启动时读取 `icons` 文件夹中的所有 PNG 图片。文件名去掉 `.png` 后就是任务中的模板名：

```text
icons/auto.png              -> auto
icons/start_loop.png        -> start_loop
icons/back_to_main_menu.png -> back_to_main_menu
```

模板名不需要扩展名。多个候选模板可用英文逗号或中文逗号分隔。

### 5.2 制作建议

1. 截取稳定、清晰且有辨识度的小区域。
2. 避免动态数字、倒计时和变化背景。
3. 截图时保持分辨率、窗口大小和系统缩放稳定。
4. 保存为 PNG 并放入 `icons` 文件夹。
5. 重新启动程序，或在步骤中重新绑定图片。

如果界面元素尺寸或布局变化明显，应为新环境重新制作模板。

## 6. 任务与预设

### 6.1 预设类型

- `custom`：自定义任务，保存于 `saved_tasks.json`，**始终在下拉框里**。
- 用户预设：通过“新建预设”创建，保存于 `saved_presets.json`。
- `daily`（内置每日任务）/ `side`（内置歧路任务）：`tasks.py` 里仍有它们的默认步骤，但**当前被删除名单屏蔽、不会出现在下拉框里**。该名单保存在 `saved_presets.json` 的 `__deleted__` 数组（当前为 `["2","cs","daily","side","导出测试","测试"]`，**以实际文件为准**），程序每次保存预设都会原样保留它。
  确需恢复这两个内置预设时：**先关闭程序**，从 `saved_presets.json` 的 `__deleted__` 里删掉 `"daily"` / `"side"`，再启动程序。

每个预设拥有独立的步骤、启用状态、组结构、组顺序和空组状态。切换预设时，程序会先保存当前预设，再加载目标预设。

### 6.2 创建预设

1. 点击“新建预设”。
2. 输入名称，不能使用 `custom`，也不能与现有名称重复。
3. 切换到新预设。
4. 点击“新增组”或“新增步骤”编排流程；**没有分组的步骤直接显示在根层**（不会自动生成「默认分组」容器），选中某个组或在组内新增时才会加入对应组。
5. 修改步骤后点击“应用修改”。

### 6.3 复制到其它预设

1. 选择源预设，包括 `custom`。
2. 用 Ctrl/Shift 选中组或步骤。
3. 点击“复制到预设”。
4. 选择目标预设。
5. 点击“复制并切换”并确认追加。

选中组会复制该组及子组内的步骤；选中步骤只复制对应步骤。复制会追加内容，不会覆盖目标预设。

### 6.4 删除预设或组

- “删除预设”删除整个预设，删除状态会在重启后保留。
- “删除”删除选中的步骤或组。
- 删除组会同时删除组内和子组内的步骤。
- 删除空组不会自动恢复，组结构会随预设保存。

### 6.5 导出和导入预设

#### 导出

1. 在“执行功能”中选择要导出的预设。
2. 点击“导出预设”。
3. 选择 ZIP 文件保存位置。
4. 导出的 ZIP 会包含当前预设的全部步骤、步骤设置、分组结构、蓝图连接关系、步骤布局、缩放比例和已绑定的 PNG 图片。

#### 导入

1. 点击“导入预设”，选择 `.zip` 预设文件。
2. 输入导入后的预设名称；名称不能使用 `custom`。
3. 如果名称已存在，可选择覆盖原预设。
4. 程序会恢复步骤、设置、分组、蓝图连接和布局，并将 ZIP 中的 PNG 图片复制到工程的 `icons` 文件夹。
5. 导入完成后程序会自动切换到新导入的预设并重新加载图片模板。

导入包只会处理根目录 `preset.json` 和 `icons/` 目录中的 PNG 文件，不会执行 ZIP 中的脚本，也不会解压其它文件到工程目录。导入前建议备份同名预设和 `icons` 文件夹。

### 6.6 重命名预设与手动保存

- **重命名预设**：在“执行功能”里选中要改的预设，点击“重命名预设”并输入新名称。`custom` 不能改名，新名称也不能与现有预设重复。
- **保存当前任务**：把当前预设的内容立即写回磁盘（`custom` → `saved_tasks.json`，其它预设 → `saved_presets.json`）。多数编辑动作本身就会保存——「应用修改」、勾选启用、增删/移动/复制步骤、框选识别区域都会自动落盘——所以正常使用**不需要**手动点它；在手工改过 JSON、或想立刻确认落盘时再点。

## 7. 编辑普通步骤

### 7.1 新建和保存

1. 选择目标预设和目标组。
2. 点击“新增步骤”，选择 `normal` 或 `advanced`（可直接创建的类型见 §4.3）。
3. 填写右侧表单。
4. 点击“应用修改”。

点击“应用修改”后会立即写回当前预设对应的 JSON 文件（等效于自动执行一次“保存当前任务”，见 §6.6）。

### 7.2 字段说明

- **启用状态**：该步骤是否参与执行（等同于列表里的勾选）。
- **多模板时**：绑定了多张候选模板时挑哪一张——置信度最高（默认）/ 最左 / 最右 / 最上 / 最下。
- **步骤名称**（任务字段 `description`）：列表和日志中显示的名称。
- **模板名**：对应 `icons` 中的 PNG 文件名。
- **匹配阈值(0-1)**：模板识别所需的最低匹配置信度。未设置独立值时继承 `config.py` 的 `THRESHOLD`。
- **用文字识别代替模板（OCR）**：勾选后这一步不再需要模板图，改用「目标文字」判断——支持用 `|` 分隔多个候选、三种匹配方式（包含 / 完全匹配 / 正则）、区分大小写与最低置信度。命中后点击文字中心，其余流程（点击开关、识别区域、超时、重试、迂回、兜底、识别调试）与模板步骤完全一致。**OCR 是可选依赖**，需要先装后端（见 §2.1）；它比模板匹配慢很多（实测约 1.2~2.1 秒/帧），建议配合「识别区域」把范围框小，并且只给"只有文字、没有稳定图标"的步骤使用。
- **点击X/点击Y**：备用固定点击坐标。
- **清空点击点**：删掉当前步骤记录的备用点击坐标（点完立即生效并保存）；清空后该步骤按**识别到的位置**点击。
- **区域选择**：当前步骤已框选的识别区域列表（每项带坐标），可切换当前要操作的那一段。
- **删除本区域**：删掉当前选中的那一段识别区域，其余段落保留。
- **下一模板**：点击后等待出现的模板名。
- **框选出现位置**：限制“下一模板”出现结果的等待区域；该区域目前为单个矩形。
- **超时**：等待识别的最长时间，单位为秒；`0` 表示不限制。
- **失败重试次数 / 重试间隔(秒)**：连续「没识别到」达到这个次数之后才判定该步骤失败（再走迂回 / 超时跳转 / 可选跳过）。默认 `0` = 不重试；重试只在本次步骤的时间预算内进行，不会让总耗时失控。
- **等待方式**：画面变化、下一模板出现、画面变化后下一模板出现。
- **完成后等待**：进入下一步前额外等待的时间。
- **点击**：是否执行鼠标点击。
- **必须识别到图片再点击**：未识别到模板时不使用未知位置点击。
- **可选步骤（跳过）**：失败时继续后续步骤。
- **框选识别区域**：为当前步骤追加一段识别区域，可以重复添加多段区域。
- **清空识别区域**：删除当前步骤的全部识别区域，恢复全屏识别。

### 7.3 记录备用点击点

1. 选中步骤并点击“记录点击点”。
2. 编辑器窗口暂时隐藏。
3. 在目标程序中单击实际需要点击的位置。
4. 编辑器恢复后，坐标会写入“点击X”和“点击Y”。
5. 想取消这个备用点，点「点击: X/Y」右侧的**「清空点击点」**——该步骤随即回到“按识别到的位置点击”。

### 7.4 框选识别区域

1. 选中步骤并点击“框选识别区域”。
2. 拖出第一段目标可能出现的矩形。
3. 松开鼠标后，再次点击“框选识别区域”并选择其它矩形；每框一次就多一段区域，
   新框的那段会成为「区域选择」里的当前项。
4. 程序只在已添加的区域内识别，并合并各区域的匹配结果。
5. 用「删除本区域」删掉当前那一段（其余保留），或点「清空识别区域」删掉全部区域
   并恢复全屏识别。

> 识别区域**只能通过框选产生**，界面不提供手工输入坐标的控件。下拉框里每一项都
> 带着该段的坐标，便于核对；框错了就删掉重框。

按 `Esc` 可取消框选。窗口布局变化后应重新框选。

一个步骤可以绑定多张候选模板（用英文逗号或中文逗号分隔）。执行时会同时识别这些模板，并按步骤面板上的**「多模板时」**下拉框决定挑哪一张：选置信度最高的那张（默认）、选屏幕最左的、最右的、最上的、最下的。位置类策略在坐标并列时优先置信度更高者。

## 8. 特殊步骤

### 8.1 `keyboard_move`：键盘移动

用于 3D 界面移动。按顺序添加按键和持续时间，例如 `W 1.0s`、`A 0.5s`，并可设置执行前延时和执行后等待。

### 8.2 `key_press`：单次按键

用于发送一次按键。可配置按键、执行前延时、按住时长和执行后等待，例如 `E` 或 `ESC`。

### 8.3 `drag`：鼠标拖曳

填写起点 X/Y、终点 X/Y 和拖动时长。坐标是屏幕坐标，不会自动适配窗口大小或分辨率。

### 8.4 `click_until_gone`：持续点击

按设定间隔点击记录的位置，直到识别到目标模板或画面发生变化。可以重复点击“绑定图片”添加多个候选模板，任一模板识别到即停止；也可以重复点击“框选识别区域”添加多个分段区域。点击间隔表示两次点击开始之间的目标时间；识别和点击本身耗时超过该值时，实际频率会受处理速度限制。可配置目标模板、点击间隔、超时时间、备用点击点、画面变化条件、`stop_delay` 和超时后是否继续下一步。绑定多个图片时也可以直接在输入框中使用英文逗号或中文逗号分隔。

### 8.5 迂回步骤

普通步骤可以配置条件分支。迂回设置中可以分别指定“未识别时跳到”和“识别成功后跳到”的主流程步骤：识别成功后执行成功跳转，未识别时先执行迂回子步骤，再执行未识别跳转。留空表示继续下一步；原有 `detour_jump_to` 配置继续作为未识别跳转使用。高级步骤可使用多个候选模板，迂回子步骤不允许继续触发迂回，避免递归循环。

### 8.6 停止脚本

点击“停止”后，程序会通过停止信号中断识别轮询、步骤等待、按键持续时间、持续点击间隔、循环等待和拖曳过程。拖曳被中断时会释放鼠标左键。

### 8.7 蓝图步骤与连接点

- **条件步骤**：配置一个或多个模板，使用 `all`、`any` 或 `not` 运算，并从成立/不成立连接点连接目标步骤。
- **选择步骤**：根据当前值匹配 `值:步骤号` 分支，未匹配时使用默认连接点。
- **循环步骤**：设置循环次数、循环体步骤和退出步骤。
- **事件步骤**：等待事件模板出现，超时可跳转到指定步骤。
- **延迟步骤**：等待指定秒数后继续，等待期间可以停止脚本。

蓝图窗口支持步骤拖动、框选、多选、复制粘贴、折叠、重命名、颜色、注释、网格吸附、自动排列和连线转折点。步骤两侧的连接点用于建立流程连接；右键连线可添加多个转折点，选中连线后才显示其转折点。

## 9. 不同分辨率和缩放比例

### 9.1 配置差异

- **图片模板**：使用灰度模板匹配，并默认启用多尺度匹配，允许模板在 `0.8` 到 `1.2` 倍范围内变化。
- **固定点击点**：记录的是屏幕坐标，不会自动换算。
- **识别区域**：主识别区域支持多个分段矩形；“下一模板”出现位置仍为单个矩形。所有坐标与录制时相关，窗口布局变化后应重新框选。
- **拖曳步骤**：起点和终点是屏幕坐标，拖动时长控制整个拖曳过程，必须重新设置坐标。
- **键盘移动**：按键和时间可复用，但速度、帧率和视角变化可能影响结果。

### 9.2 1920×1080

工程内任务坐标按 1920×1080 环境记录。若分辨率、窗口位置、窗口大小和系统缩放一致，可以先直接测试，但仍需确认模板和点击位置。

### 9.3 1600×900、1366×768 等分辨率

1. 设置目标程序分辨率，固定窗口位置和大小。
2. 如果元素尺寸明显变化，重新截取 PNG 模板。
3. 对普通点击步骤重新记录点击点。
4. 重新框选识别区域。
5. 对拖曳步骤重新填写起点和终点。
6. 分段启用并测试，不要立即开启循环。

### 9.4 2K、4K 和 Windows 显示缩放

Windows 125%、150% 等缩放可能同时改变模板尺寸和坐标。建议固定窗口模式，重新截取模板、记录点击点和框选区域，再考虑调整匹配参数。不要只降低阈值解决分辨率问题，阈值过低会增加误识别。

**实测事实**（2026-09-28，1920×1080 @ 100% 缩放）：程序启动时 Qt 会把进程设为 per-monitor DPI 感知（`GetProcessDpiAwareness = 2`，打包版同样如此）；在 **100% 缩放**下，Qt 的逻辑坐标与截屏/点击所用的物理坐标**完全一致**（`devicePixelRatio = 1.0`），不需要任何换算。

由此可以这样判断：

- 在 **100% 缩放**下录制的坐标，拿到同样 100% 的机器上可以直接用。
- 如果系统缩放是 **125% / 150%**（或两台显示器缩放不同），Qt 逻辑坐标与物理像素会分离，**框选区域和点击坐标都会偏，而且偏差随坐标增大而增大**。这类机器上必须重新框选/重新记录点击点，必要时把系统缩放调回 100%。

### 9.5 目标窗口模式

选择目标窗口后，程序优先截取该窗口区域，即使窗口不在前台也可以识别。窗口移动、调整大小或切换 DPI 后，应重新检查模板、点击点、识别区域和拖曳坐标。

### 10.3 `config.py` 常用参数

- `THRESHOLD`：模板匹配阈值，默认 `0.8`。
- `APP_VERSION` / `UPDATE_REPO` / `CHECK_UPDATE_ON_START` / `UPDATE_CHECK_TIMEOUT` / `UPDATE_PROXY`：版本号与自动更新检查。`UPDATE_PROXY` 留空表示自动探测（环境变量 → Windows 系统代理 → 直连）。
- `USE_MULTI_SCALE`：是否启用多尺度匹配。
- `SCALE_RANGE`：多尺度范围，默认 `(0.8, 1.2)`。
- `SCALE_STEP`：多尺度步长，默认 `0.05`。
- `MONITOR_INDEX`：截屏监视器编号，`0` 表示全部屏幕，`1` 表示主屏（默认）。
- `DEFAULT_TIMEOUT`：默认等待超时时间，默认 `50.0` 秒。
- `DEFAULT_POLL_INTERVAL`：模板扫描间隔，默认 `0.1` 秒。
- `SHOW_PREVIEW`：是否弹出 OpenCV 预览窗口（默认 `False`，调试识别区域时可用）。
- `CLICK_DELAY`：点击前后移动鼠标的延时，默认 `0.05` 秒。
- `USE_WINDOW_MODE` / `TARGET_WINDOW_TITLE`：是否只识别指定窗口 / 目标窗口标题。**这两个会被界面覆盖**：点「开始执行」时程序按「目标窗口」下拉框的选择临时赋值，运行结束后自动还原（见 `execution_control._start_worker` 与 `_restore_config_after_run`）。所以**想固定目标窗口请用界面下拉框**，改这里只在直接调用引擎（不经过界面）时有效。

修改全局配置后请重新启动程序。

## 11. 常见问题

### 11.1 图片识别不到

检查模板是否在 `icons` 文件夹、模板名是否正确、目标窗口和页面是否正确、模板是否包含动态内容或被遮挡。然后重新截图或框选区域，最后再调整 `THRESHOLD`、`SCALE_RANGE` 或 `SCALE_STEP`。

### 11.2 点击位置不准确

重新使用“记录点击点”。窗口移动、缩放或分辨率变化后，旧坐标可能失效。

### 11.3 操作了错误窗口

停止脚本，点击“刷新窗口”，重新从下拉框选择目标窗口。确认无误前不要开启循环。

### 11.4 启动时报缺少模块

重新安装依赖（推荐 `python -m pip install -r requirements.txt`，见 §2.1），并确认**安装依赖和启动程序用的是同一个 Python**：

```powershell
python -c "import numpy, cv2, mss, pyautogui, pygetwindow, PySide6; print('依赖正常')"
```

> 打包版（§2.3）不需要 Python，出现此问题只可能是源码运行方式。

### 11.5 预设或空组重新出现

修改预设后让程序正常保存，再切换或关闭程序。不要在程序运行时直接覆盖 JSON 文件，并检查 `saved_presets.json` 是否为合法 JSON。

### 11.6 步骤超时或脚本停止

确认目标页面、模板、等待方式和下一模板设置正确。适合容错的步骤可勾选“可选步骤（跳过）”；不适合无限等待的步骤应设置合理超时。

### 11.7 `icons` 里没有图片 / 图片被清空

**程序照常可以打开**，只是识别类步骤会全部"未识别"——启动时日志框会给出一条提示（`icons` 里没有可用的模板图）。把图片放回 `icons` 文件夹、或在步骤里重新绑定图片即可恢复。

- 源码运行：`icons/` 就是工程里的那个文件夹。
- 打包版：图片在 `_internal\icons` 里。**清理图片不影响启动**，但如果要把新录的模板给打包版用，拷进该目录即可（也可以整体重新打包）。
- 注意：删图只影响识别，不会影响任务/预设数据；反过来删数据文件才会影响预设（§10.2）。

### 11.8 打包版双击没反应

先确认 `VisionFlow_Automator.exe` 所在的整个目录都在（`_internal` 不能单独挪走或删除），且放在**可写目录**（§2.3）。若仍然没反应，用源码方式运行一次（`python gui_pyside6.py`）即可在控制台看到真实报错。

## 12. 安全建议

运行前确认：

- 目标程序已打开并停留在预期页面。
- 所有需要的 PNG 模板都在 `icons` 文件夹中。
- 已从“目标窗口”下拉框选择正确窗口。
- 第一次测试未勾选“循环执行”。
- 只启用了准备测试的步骤。
- 备用点击点和识别区域适用于当前窗口。
- 已确认脚本可能移动鼠标并发送键盘输入。

先分段测试，再启用完整流程。运行过程中不要将重要文件、设置界面或其它需要人工确认的窗口置于可能被误点击的位置，也不要在未验证配置的情况下长时间无人看管运行。
