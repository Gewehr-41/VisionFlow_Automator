## 2026-10-26　蓝图连线"可用化" + 两个会改坏状态/画面的交互 bug

> **提交**：9 个（`3d1b5c1` → `7e19a46`）
> **测试**：411 → **446**（+35，全绿）
> **改动量**：16 个文件 **+1,262 / −38** 行（其中测试 8 文件 +777 行）

### 1. 一句话总结

把蓝图里"连不准、只能一条条删"的连线交互补成可用（端口命中修复 + Ctrl+右键批量划断 + Ctrl 框选批量删），
并修掉两个**会真的改坏东西**的 bug：折叠的分组被程序化选中展开后**把折叠状态写坏落盘**；
右侧面板在"未选中步骤 / 组设置"下残留错位的输入框与下拉框。

### 2. 背景：为什么是这几处

所有者今天先问的是"蓝图模式的连接点还是不太灵敏"，接着提"做 Ctrl+右键划断多条连线；连线可框选"，
随后两个反馈分别指向折叠组与右侧面板。四件事都在**交互层**，都要"手感可验证"，所以统一采用
**先量化症状 → 改 → 复测同一组指标 → 变异验证**的流程，而不是"看着像好了"。

### 3. 做完的工作（6 项）

#### 3.1 蓝图连线"点不准"（#77，`3d1b5c1` + `7b4c327`）

| 项 | 内容 |
|---|---|
| 症状 | 瞄准「未识别 / 成功 / 超时」等相邻端口时经常连错；按偏一点就完全起不了拖 |
| 根因（三个叠加） | ① 端口判定是"按 `ports()` 顺序，第一个落进 14px 容差的就返回"，而端口间距只有 16/20/32px → 重叠区永远归"顺序"：100% 缩放**错抓 31%**，43% 缩放**错抓 43% + 漏判 7%**；② 容差是固定场景像素，缩小画布后判定区跟着缩成针尖；③ 端口圆圈画在边框上，按偏 1px 到节点外 `itemAt()` 就返回 None → **根本起不了拖**；④ 按下时"先判连线"的分支会先命中连线图元并 return，走不到端口判定 |
| 改法 | 端口判定改为**最近者胜**；容差按**屏幕像素**换算（`max(14, min(12/缩放, 22))`）；新增 `_node_at_scene_pos(pos, margin)` 允许节点外 10px 起拖、松手时外 12px 仍算接上；按下顺序改为**端口优先于连线**；新增悬停白圈 + 十字光标（按下前就能看清会连哪个口）；悬停状态要能扛住 `refresh()` 销毁节点（`RuntimeError` 兜底） |
| 验证 | 新增 `tests/test_blueprint_ports.py` 10 条（绘制位置命中、重叠区不再被"顺序"抢走、容差随缩放、节点中部不算端口、边缘外起拖、左侧输入口、松手余量、**走真实事件链**的按下→拖动→松手、悬停设/清、refresh 后悬停不崩）；复测 ±3 屏幕像素瞄准：100/70/50/43% 缩放命中目标端口均 **100%**，漏判 0%，边缘外 1/3/6/10px 均可起拖 |
| 结果 | 411 → **421** |

#### 3.2 Ctrl+右键划断多条连线（`1b19c72`）

- **划断**：拖动时用 `QPainterPathStroker` 把划断路径加粗成 **8 屏幕像素**的"切线区域"，与每条线的 `path()` 求交；
  命中的线松手前先 `set_cut_preview(True)` 标红（`paint` 里压一层红色描边），松手一次性交给窗口处理
- **防误切**：拖动短于 **6 屏幕像素**不算（Ctrl+右键单击仍然弹菜单，不压菜单）
- **一次手势 = 一条撤销记录**：新增 `_delete_connections(edges)`，一批只 `_push_history()` 一次、`refresh()` 一次、落盘一次；
  原 `_delete_connection` 变成单条包装，迂回开关的对称处理抽到 `_clear_connection_fields`（行为不变）
- **右键菜单压制**用 **500 ms 时间窗**而不是 `QTimer.singleShot(0)`：右键松开 → 菜单请求 → 定时器三者先后顺序不保证
- **顺带修掉旧 bug**：按下处理原来不区分按键，**在连接点上按右键会进入拉线状态、右键松开甚至能建出一条连接**；现在只有左键能拉线

#### 3.3 连线可框选 + 用 Ctrl 区分"框线/框步骤"（`1b19c72` + `02872c0`）

- 给 `BlueprintWireItem` 加 `ItemIsSelectable`，`_apply_wire_geometry` 的高亮判据补上 `edge["wire"].isSelected()`
- **首版是"节点优先"，被实测推翻**：用真实橡皮筋（不是直接 `setSelected`）验证时，框选区**只要含一个节点，连线就永远选不上**
  （实测 0/2，而 `scene.items(框)` 里两条线都在）→ 改成**按下时的 Ctrl 决定本次框选选哪一类**：按 Ctrl 只框连线、不按只框步骤/分组，另一类从选择集剔除
- 批量删除：`Delete` 键、右键「删除选中的 N 条连接」都走 `_delete_connections`
- 结果：421 → **434**

#### 3.4 选中连线时多出的白色虚线框（`e61e40c`，**自引入回归**）

| 项 | 内容 |
|---|---|
| 症状 | 所有者：「拖动选择了线后，线的外围会出现被选择白色虚线框」 |
| 根因 | `QGraphicsPathItem::paint` 在 `State_Selected` 时会调 `qt_graphicsItem_highlightSelected`，在**图元外接矩形**上补画一圈虚线；连线的 `boundingRect` 还额外放宽了 14px，所以像凭空多出一个框 |
| 改法 | `paint` 里复制 `QStyleOptionGraphicsItem` 并清掉 `State_Selected` 再交给基类；选中态只由连线的白色描边表达 |
| 验证 | 同一条线"选中/未选中"两次**离屏渲染的像素必须完全相同**（变异验证：把选中位传回去 → 立刻失败，多出的正是 `\xff` 虚线像素）；另加一条"高亮仍要画出来"防止连高亮一起清掉 |
| 结果 | 434 → **436** |

#### 3.5 折叠的分组被"选中步骤"自动展开，而且折叠状态被写坏（#79，`9004e77`）

- **所有者反馈**：4 个组、折叠上面 3 个，点最后一个组里步骤的开启/关闭，**每点一次第 1 组就自动展开**
- **真因链条**：点勾选框 → `on_item_changed` → 0 ms 后 `refresh_task_list()` 重建树 → 末尾 `select_task_index()` 调 `setCurrentItem`；
  `QTreeView` 为让"当前项"可见会在内部 `scrollTo` 时**展开被折叠的祖先组**；更糟的是这次展开发生在 `blockSignals(False)` **之后**，
  触发 `itemExpanded` → 把"展开"**写回分组元数据并落盘**（实测 `{'g1': False}` → `{'g1': True}`）——折叠状态不是"看起来变了"，而是真的被改坏
- **改法**：`select_task_index` 先快照各组展开状态、期间置 `_suppress_group_expand_sync`，选完按快照恢复；
  `_on_group_expanded_changed` 在标志置位时直接返回（程序化选中造成的临时展开不是用户操作）
- **验证**：新增 `tests/test_group_collapse.py` 4 条；变异验证两半各自都有测试盯着（去掉快照 → 4 条全红，报错正是 `{'g1': True}`；去掉元数据防护 → 3 条在元数据断言上红，视觉断言仍过）
- **复现坑**：第一版复现失败——窗口没 `show()` 时 `scrollTo` 不展开祖先组；真实窗口才有这个行为
- 结果：436 → **440**

#### 3.6 右侧面板在"未选中步骤 / 组设置"下残留「步骤名称·启用状态·多模板时」（#80，`1abf19e` + `37c5629` + `7e19a46`）

| 项 | 内容 |
|---|---|
| 症状（所有者截图） | 未选中步骤时面板仍显示 `步骤名称:` 空输入框 + `启用状态: ☐启用步骤 多模板时:[…]`；选中分组时同样残留；延迟/按键/移动/拖曳等**没有模板识别**的步骤也显示「多模板时」 |
| 根因 | 这两行当初是 `layout.addLayout(name_form)` —— **裸 QFormLayout 直接挂进布局**，没有控件句柄，`clear_editor()` / `_clear_editor()` / `_load_editor_for_group()` 想隐藏也没有对象可隐藏；「多模板时」标签与下拉框是无条件构造的，从未按类型显隐 |
| 改法 | ① 包进 `self.name_block`（QWidget 内嵌 QFormLayout），三处收起、`_update_editor_visibility` 里随选中步骤恢复；② 抽出 `self.strategy_label`，只有 `normal/advanced` 显示「多模板时」——`click_until_gone` 虽也做模板匹配，但其执行路径**不读** `get_task_match_strategy`（按函数体核实），故同样隐藏；`启用步骤` 对所有步骤类型保留 |
| 验证 | 新增 `tests/test_editor_visibility.py` 6 条，**两个窗口各验证一遍**；属性契约里补 `name_block`/`strategy_label`；变异验证两处（改成"总是显示多模板时" → 两种窗口 × 五种类型全红；去掉清空面板的隐藏 → 未选中用例立刻失败） |
| 顺带 | **测试去环境化**：本地 `saved_tasks.json` 已被清空（实测 0 条），`test_capture_mixin` / `test_editor_roundtrip` / `test_config_handling` 以 `IndexError` / "预设为空" 误报 20 条；先用 `git stash` 在 HEAD 上复现同样失败证明与本改动无关，再给三套用例装固定夹具 |
| 结果 | 440 → **446** |

### 5. 验证方式（这些结论为什么可信）

- **先量化症状再改**：连线命中用"标注端口 vs 代码选中的端口"对比（31%/43% 错抓、7% 漏判）；折叠 bug 直接打印元数据前后值
- **用真实交互链而不是直调私有方法**：`QMouseEvent` 构造 + `mapFromScene` 坐标换算，走 `mousePressEvent`→`mouseMoveEvent`→`mouseReleaseEvent`；
  框选用**真实橡皮筋**（`show()` 过的窗口）验证，"节点优先"就是被这条推翻的
- **离屏渲染像素比对**：选中连线不能改变图元自身渲染（逐字节比较两张 `ARGB32`）
- **变异验证 8 处**：每条新守卫都先故意破坏一次，确认它真的会失败
  （最短拖动距离、节点优先、`prefers_wires` 分支、`State_Selected` 清位、快照恢复、元数据防护、多模板时按类型显隐、清空面板隐藏）
- **对照排除**：大面积失败先用 `git stash` 把改动暂存、在 HEAD 上复跑，证明"不是我改坏的"，再定位到环境数据
- **数据隔离**：所有新测试用临时目录 + `VF_DATA_DIR`，不触碰真实 `saved_*.json`
