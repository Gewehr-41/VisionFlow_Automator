# legacy/ — 已退役的旧界面

## 这个目录是什么

存放**已退役但保留备查**的代码。目前只有 `gui.py`。

## gui.py 是什么

`gui.py` 是本项目**第一代 Tkinter 图形界面**（6,353 行，单一类 `AutoScriptGUI`，196 个方法）。
它早于 PySide6 版 `gui_pyside6.py`，是 2026 年 8 月下旬那次界面迁移之前的实现。

## 为什么退役

2026-09-28 经确认：**后续只使用 PySide6 界面**，`gui.py` 不再维护。

它退役前最后修改于 **2026-08-26**，此后项目其它文件持续演进到 8/31，
而它一直停留在旧状态。

### 保留而不删除的原因

它并非"质量更差的旧版"——它在下面 4 点上曾经领先于 PySide6 版。
这 4 项能力已于 **2026-09-28 全部移植到 `gui_pyside6.py`**（提交 `2d1820a`）：

| 能力 | 说明 |
|---|---|
| 嵌套分组树渲染 | 按 `parents` 元数据递归渲染组层级 |
| 分组折叠状态持久化 | 把展开/折叠写入 `__group_metadata__` |
| 蓝图缩放比例恢复 | 打开蓝图时应用 `layout_data["zoom"]` |
| 跨预设复制选中项 | 把选中的组/步骤追加到另一个预设 |

因此**当前版本已不再依赖本目录**，它纯粹是历史留存。

## ⚠️ 重要：不要用它打开数据文件

`gui.py` 与 `gui_pyside6.py` **共享同一批 JSON 数据文件**
（`saved_tasks.json` / `saved_presets.json` / `saved_blueprint_layouts.json` /
`saved_blueprint_graphs.json`）。

它含有若干**已知且不会修复**的数据破坏性问题，一旦运行并保存，可能覆盖新界面的数据：

| 问题 | 后果 |
|---|---|
| **保存前有蓝图校验闸门**（`save_current_tasks`） | 蓝图一旦非法，**后续所有编辑静默不落盘**，且调用方不检查返回值 → 改动全部丢失 |
| **启动时清空分组层级** | 冷启动会丢失嵌套层级、组顺序、折叠状态、空组 |
| 删除步骤只重编号 4 个字段 | 跳转目标错位（PySide6 版已修为统一的 10+ 字段） |
| 4 处跨线程操作 Tk | 偶发卡死或异常 |
| 未传 `completion_callback` | 在 worker 线程创建 Tk 模态框，主窗口按钮长时间卡住 |

**如需查看旧实现，请只读代码，不要运行它去打开现有数据。**

如果确实需要用旧界面，请**先把 4 个 JSON 备份到别处**。

## 如何运行（如确有必要）

启动脚本 `启动脚本编辑器.vbs` 已更新为指向本目录。它会：

1. 把工作目录设为项目根目录（这样 `import config` / `import main` 等才能解析）
2. 以隐藏窗口方式运行 `legacy\gui.py`

也可以手动运行：

```powershell
cd <项目根目录>          # 必须，否则导入会失败
python legacy\gui.py
```

> 注意：`gui.py` 依赖**工作目录**而不是自己的位置来解析 import，
> 所以必须在项目根目录下启动，不能 `cd legacy` 再运行。

## 会不会被删除

不会主动删除。它已完整纳入 git 历史，即使将来删除也可随时恢复：

```powershell
git log --oneline --follow -- legacy/gui.py      # 查看它的完整历史
git checkout <commit> -- legacy/gui.py           # 从任意提交恢复
```
