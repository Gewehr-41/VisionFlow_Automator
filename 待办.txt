PySide6 UI 框架迁移

一、迁移原则
- 保留任务执行、模板识别、数据文件格式和节点模型，优先只替换 UI 层。
- 不在同一窗口中混用 Tkinter 和 PySide6，避免两个事件循环和控件对象互相调用。
- 先创建新的 PySide6 入口和界面文件，旧版 gui.py 保留作为可回滚版本。
- 每完成一个阶段都启动程序并进行实际操作验证，避免最后一次性排查大量问题。

二、准备工作
- 安装依赖：在项目虚拟环境中安装 PySide6，并记录版本。
- 增加项目依赖说明，更新 README.md 的安装和启动命令。
- 检查 Python 3.10、Windows 和当前打包/启动方式与 PySide6 的兼容性。
- 规划新的入口文件，例如 gui_pyside6.py；迁移稳定后再决定是否替换 gui.py。
- 梳理 gui.py 中的状态变量、数据读写函数和纯业务函数，明确哪些代码可以直接复用。
- 建立旧 Tkinter 版本的启动回退方式，迁移期间不要删除旧入口。

三、第一阶段：主窗口和基础控件
- 使用 QApplication、QMainWindow 和中央布局重建主窗口。
- 重建顶部工具栏：循环执行、预设选择、预设管理、目标窗口、开始/停止/暂停/单步等控制。
- 使用 QComboBox、QPushButton、QCheckBox、QLabel、QLineEdit、QListWidget 或 QTreeWidget 替换对应 Tk 控件。
- 使用 QSplitter 重建左右面板和日志区域，保留窗口最小尺寸、伸缩比例和状态提示。
- 使用 Qt Designer 或集中式 Qt Style Sheet 统一字体、颜色、间距和控件状态，避免大量散落的样式设置。
- 迁移预设创建、重命名、复制、导入、导出和删除对话框。
- 迁移任务列表的选择、多选、双击启用、Enter 批量切换、拖拽排序和分组显示。
- 迁移普通步骤和特殊步骤编辑表单，保证字段默认值、旧字段兼容和保存行为不变。

四、第二阶段：信号、线程和任务执行
- 将按钮命令和 Tkinter bind 回调改为 Qt signal/slot。
- 保证所有控件更新只发生在 Qt 主线程，不从后台线程直接操作界面。
- 将任务执行线程的日志、状态、当前步骤、完成和异常结果通过 Signal 发送给主窗口。
- 评估现有 threading.Thread 是否继续保留；如改用 QThread，明确 worker 生命周期、停止、暂停和单步语义。
- 将 root.after 定时器替换为 QTimer 或线程安全的 Qt 信号调度。
- 移除 main.py 中独立创建 Tk 根窗口的完成提示，改为由 PySide6 主窗口接收完成信号后显示 QMessageBox。
- 检查停止脚本、关闭窗口和后台线程退出顺序，防止进程残留或窗口关闭后仍回调 UI。

五、第三阶段：文件、图片和区域选择
- 使用 QFileDialog 替换文件选择、导入和导出对话框。
- 使用 QColorDialog 替换组颜色选择器。
- 使用 QMessageBox 替换提示、确认、错误和蓝图检查结果弹窗。
- 使用 QImage/QPixmap 或现有图像库加载模板预览，确认图片生命周期不会导致空白或资源泄漏。
- 重写点击点捕获：使用透明置顶 QWidget 或 QDialog 接收全局鼠标位置，再通过信号返回坐标。
- 重写区域框选：使用透明覆盖层绘制选择矩形，支持取消、确认、屏幕边界和多显示器坐标。
- 核对 Qt 的 devicePixelRatio、Windows 显示缩放、截图坐标、目标窗口坐标之间的换算。
- 保持现有模板路径、PNG 文件名、绑定图片和导入预设行为不变。

六、第四阶段：蓝图编辑器
- 使用 QGraphicsView + QGraphicsScene 重写蓝图画布，不直接照搬 Tk Canvas 绘制代码。
- 将节点、组容器、输入/输出连接点、连线和转折点分别设计为可交互图元。
- 实现节点点击、多选、框选、拖拽、组整体移动、折叠/展开和右键菜单。
- 实现画布平移、缩放、滚轮操作、网格吸附、自动排列和选中项对齐。
- 迁移普通连接、成功/失败/超时出口、迂回连接和连接点高亮逻辑。
- 迁移 Ctrl+Z/Ctrl+Y/Ctrl+C/Ctrl+V 快捷键，并确认快捷键只作用于蓝图窗口。
- 保持 saved_blueprint_graphs.json 和 saved_blueprint_layouts.json 的字段及坐标语义兼容。
- 蓝图编辑器完成前，不切换默认启动入口，避免影响现有任务执行功能。

七、兼容性和回归验证
- 启动后检查主窗口、预设列表、任务列表、编辑表单和日志显示。
- 验证 custom、daily、side 和用户预设的加载、保存、复制、导入和导出。
- 验证普通、高级、条件、选择、循环、事件、延迟、按键、键盘移动、拖曳和持续点击步骤。
- 验证暂停、继续、单步、从当前步骤执行、停止和循环执行。
- 验证目标窗口刷新、窗口移动/缩放、模板识别、点击坐标和识别区域。
- 验证单显示器、多显示器和 Windows 不同缩放比例下的框选与坐标转换。
- 验证蓝图连接检查、不可达步骤检查、布局保存、撤销/重做和主界面同步刷新。
- 运行现有测试，并补充 UI 冒烟测试和任务执行回归测试；测试中避免真实误操作目标窗口。
- 检查关闭窗口时后台线程、定时器、覆盖层和蓝图窗口是否全部释放。

八、切换和回滚
- 新 UI 完成基础回归后，再修改 启动脚本编辑器.vbs 指向新的 PySide6 入口。
- 更新 README.md 中的启动方式、依赖安装和故障排查说明。
- 保留旧 gui.py，至少观察一轮实际使用后再考虑删除或归档。
- 切换后如果出现执行逻辑、坐标或数据兼容问题，立即恢复旧入口，不修改任务 JSON 作为临时规避方案。
- 最终确认不再导入 tkinter，不再创建 Tk 根窗口，也不存在 Tk/PySide6 两套 UI 同时运行。

迁移注意事项
- PySide6 控件不能直接替换 Tkinter 控件，原有 pack/grid/place 布局、变量绑定和 bind 事件需要重新实现。
- Qt 只能在 QApplication 事件循环中运行；不要在后台线程创建 QWidget、弹窗或直接修改控件。
- root.after 与 QTimer 的执行时机不同，截图轮询、拖拽自动滚动和状态刷新需要重点验证。
- QGraphicsView 的坐标、视口坐标、场景坐标和屏幕坐标必须分开处理，不能直接复用 Tk Canvas 坐标换算。
- Windows DPI 缩放和多显示器负坐标可能影响截图框选、点击点和蓝图交互坐标。
- pyautogui、pygetwindow、OpenCV、mss 等自动化和识别依赖与 UI 框架相互独立，不要为了迁移改动其调用协议。
- PySide6 的发布体积和部署方式与 Tkinter 不同，后续打包时需包含 Qt 平台插件和相关 DLL。
- 迁移期间优先保证任务数据格式和执行结果不变，界面外观可以在功能稳定后再优化。
